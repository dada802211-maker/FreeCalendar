# カレンダーのJSON設定ガイド

## ファイルと更新方法

| ファイル | 用途 |
| --- | --- |
| `public/holidays.json` | 祝日の名称・計算条件・色 |
| `public/calendar-status.json` | 臨時休診など、特定の日付の状態・案内・色 |

開発時は `public` 内を編集します。公開済みのサイトでは公開先の同名JSON（通常は `dist` 内）を編集し、ブラウザーを再読み込みしてください。JSONだけの変更は再ビルド不要です。次回ビルドで元に戻らないよう `public` 側にも同じ変更を保存してください。

UTF-8で保存します。JSONにはコメントや末尾のカンマを書けません。取得時はブラウザーキャッシュを使用しません。

## 両ファイル共通の色設定

各祝日・個別予定のオブジェクトに、次の項目を指定します。ファイル全体の設定ではなく、項目ごとの指定です。

| 項目 | 内容 | 省略時（祝日 / 個別予定） |
| --- | --- | --- |
| `color` | 日付の数字の文字色 | `#db2777` / `#6d28d9` |
| `backgroundColor` | 日付部分の背景色 | `#fecdd3` / `#ede9fe` |
| `colorPriority` | 色の優先度。0～999の整数 | 10 / 20 |

色は `#RGB` 形式の3桁、または `#RRGGBB` 形式の6桁の16進数です。`#000` と `#000000` はどちらも黒色です。例：`#ff0000`（赤）、`#0000ff`（青）。色名、透明色、`null` は使用できません。省略は可能なので、従来のJSONも読み込めます。文字色と背景色は読みやすい組み合わせにしてください。

### 同じ日に祝日と個別予定が重なった場合

1. `colorPriority` が大きい方の色設定を採用します。
2. 同じ値なら `calendar-status.json` の個別予定を優先します。
3. 採用した項目の文字色と背景色をセットで使用します。色が省略されている場合は、その種別の省略時の色になります。もう一方の色は混ぜません。

例：祝日が10、臨時休診が20なら臨時休診の色です。祝日を優先するには、その祝日の値を30にするか、臨時休診の値を5にします。

土日よりも祝日・個別予定の設定色を優先します。今日の日付にも設定色を適用し、輪郭のある丸印で今日を示します。色の優先度は表示色だけに影響し、祝日名、祝日一覧、個別の案内は両方残ります。同じ色を指定した場合も同じ規則ですが、見た目の色は変わりません。

## calendar-status.json

日付ごとの予定を配列で記述します。以下は書式の例です。実際の診療予定に合わせて変更してください。

```json
[
  {
    "date": "2026-10-15",
    "label": "臨時休診",
    "message": "院内研修のため、終日休診いたします。",
    "color": "#6d28d9",
    "backgroundColor": "#ede9fe",
    "colorPriority": 20
  },
  {
    "date": "2026-10-20",
    "label": "午後休診",
    "message": "午前は通常どおり診療いたします。",
    "color": "#92400e",
    "backgroundColor": "#fef3c7",
    "colorPriority": 20
  }
]
```

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| `date` | はい | `YYYY-MM-DD`。0001年～2150年の実在する日付 |
| `label` | はい | 空白のみではない状態名 |
| `message` | いいえ | 詳しい案内文。改行は `\n` で記述 |
| `color` / `backgroundColor` / `colorPriority` | いいえ | 共通の色設定を参照 |

同じ日付は1件だけ指定してください。複数の案内がある日は `message` にまとめます。予定がない場合は `[]` にします。表示中の月の案内だけを日付順で表示します。個別予定から振替休日は生成しません。未設定の日が診療日であることを意味しません。

## holidays.json

1月～12月の順番で12個の配列を並べます。祝日がない月も `[]` を残します。月は配列の位置で決まり、`month` の文字列では変わりません。

次は1件の祝日オブジェクトの例です。ファイル全体をこのオブジェクトだけに置き換えず、該当月の配列内で編集してください。

```json
{
  "month": "January",
  "name": "元日",
  "type": "fixed",
  "start_year": 0,
  "end_year": 9999,
  "day": 1,
  "comment": null,
  "color": "#db2777",
  "backgroundColor": "#fecdd3",
  "colorPriority": 10
}
```

| 項目 | 説明 |
| --- | --- |
| `month` | 月名の文字列（例：`January`） |
| `name` | 祝日名。空白のみは不可 |
| `type` | 下表の計算方式 |
| `start_year` / `end_year` | 適用年の整数。0～9999、開始年≦終了年、両端を含む |
| `day` | 固定日は日番号。それ以外は通常 `null` |
| `comment` | 説明文または `null`。カレンダー下の案内には表示されない |
| `color` / `backgroundColor` / `colorPriority` | 共通の色設定。省略可 |

色設定以外の項目はすべて必要です。画面で選択できる年は0001年～2150年です。祝日計算の適用は既存の祝日法施行判定に従います。

| `type` | 内容 |
| --- | --- |
| `fixed` | 指定日の祝日。`day` 必須 |
| `second_monday` | 第2月曜日 |
| `third_monday` | 第3月曜日 |
| `vernal_equinox` | 春分の日 |
| `autumnal_equinox` | 秋分の日 |
| `conditional_holiday` | 既存の5月4日の国民の休日判定 |
| `conditional_substitute_holiday` | 既存の5月6日の振替休日判定 |

自動生成する振替休日や国民の休日にも、その日を生成した祝日項目の色と色の優先度を引き継ぎます。複数の祝日ルールが同じ日に該当する場合、祝日名の決定は既存の祝日計算の優先順位に従い、その祝日の色設定を採用します。`colorPriority` は祝日同士の計算順序を変更するものではありません。

## 読み込みエラー

不正なJSON、色形式、優先度、個別予定の日付重複・存在しない日付などはエラーになります。祝日データのエラーはカレンダーの代わりに表示し、個別予定のエラーは案内欄に表示します。ファイル名・JSON構文・項目の値を修正して再読み込みしてください。ファイルはWebサーバー経由で配信してください。
